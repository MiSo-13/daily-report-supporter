# 사용 가이드

## 업무 추가

`오늘 업무` 영역에서 내용을 작성한 뒤 `+ 업무 추가`를 누릅니다.

추가와 동시에 Markdown 파일에 저장됩니다.

## 업무 수정

목록에서 기존 업무를 선택합니다.

내용을 수정하면 `변경사항 저장` 버튼이 나타납니다.

## 저장 단축키

- Windows/Linux: `Ctrl+S`
- macOS: `Cmd+S`

새 업무 작성 중이면 추가하고, 기존 업무 편집 중이면 변경사항을 저장합니다.

## 화면 높이 조절

업무 목록과 제목/링크/주요 내용 편집 영역 사이 경계를 위아래로 드래그해 높이를 조절할 수 있습니다.

## 업무 삭제

기존 업무를 선택한 뒤 `삭제`를 누릅니다.

확인 후 현재 날짜의 Markdown 파일에서도 삭제됩니다.

## 상태

업무 상태는 세 가지입니다.

- 예정
- 진행중
- 완료

다음날 문서를 만들 때 `진행중`과 `예정` 업무만 오늘 업무로 이월됩니다. `완료` 업무는 이월하지 않습니다.

## 이전 업무 호환

현재 앱에서는 별도의 `이전 업무` 입력 영역을 사용하지 않습니다.

이전 버전에서 저장된 이전 업무 데이터는 기존 Markdown 보존을 위해 유지되지만 일일보고 생성에는 사용하지 않습니다.

## 링크

링크는 이름과 URL을 따로 입력합니다.

예:

```text
링크 이름: 1694
URL: http://naver.com
```

저장 결과:

```markdown
- 관련 문서: [1694](http://naver.com)
```

URL만 입력하면 URL 자체가 링크 이름으로 사용됩니다.

유효한 `http://` 또는 `https://` 주소를 입력하면 URL 옆의 `열기` 버튼이 활성화되고 테마의 강조색으로 표시됩니다. 비활성 상태는 muted 색상으로 구분됩니다.

## 주요 내용 Markdown

주요 내용은 Markdown으로 입력합니다. 앱이 자동으로 `- `를 붙이지 않습니다.

예:

```markdown
### 확인 내용

- 첫 번째
  - 하위 항목

**완료**
```

입력한 줄바꿈과 Markdown 문법은 저장 후 다시 열어도 유지되며 일일보고에도 그대로 들어갑니다.

관련 문서가 있으면 보고서에서 별도 줄로 출력하지 않고 업무 제목 옆에 표시합니다.

```markdown
1. 보고서 개선 문서 확인 ([Confluence](https://example.com/doc))
```

## 메모

왼쪽에서 `메모` 탭을 선택하면 날짜와 무관한 메모 공간으로 전환됩니다.

- `+ 새 메모`: 새 Markdown 파일 생성
- 제목: 메모 목록에 표시되는 이름
- 검색: 모든 메모의 제목과 본문 검색
- 삭제: 현재 메모 파일 삭제
- 저장: `Ctrl+S` / macOS `Cmd+S`
- 목록 항목 드래그: 메모 표시 순서 변경 및 저장

### Markdown 편집

`편집` 탭은 Raw Markdown을 그대로 작성합니다. Tab 입력 폭은 현재 앱 폰트의 공백 폭을 기준으로 약 4칸으로 맞춥니다.

`미리보기` 탭은 Markdown이 적용된 상태로 표시되며, 그 상태에서도 직접 내용을 수정할 수 있습니다. 미리보기에서 수정한 내용은 다시 Markdown으로 변환되어 저장됩니다.

미리보기 편집은 Markdown 표현을 정규화할 수 있으므로 원문 문법이나 공백을 정확히 유지해야 할 때는 `편집` 탭을 사용합니다.

#### 바로 서식 적용

미리보기에서 줄 시작에 아래 문법을 입력하고 Space를 누르면 바로 서식이 적용됩니다.

- `# `, `## `, `### `: 제목
- `- `, `* `: 글머리 목록
- `1. `: 번호 목록
- `> `: 인용
- `\`\`\` `: 코드 블록
- `--- `: 수평선
- `- [ ] `: 미체크 체크박스
- `- [x] `: 체크된 체크박스

체크박스는 화면에서 직접 클릭해 상태를 전환할 수 있습니다.

`미리보기` 탭에 마우스를 올리면 지원하는 Markdown 단축 문법을 툴팁으로 확인할 수 있습니다.

- `Ctrl/Cmd+B`: 굵게
- `Ctrl/Cmd+I`: 기울임

### 메모 순서

메모 목록의 항목을 위아래로 드래그해 원하는 순서로 배치할 수 있습니다. 변경된 순서는 `memos/.order.json`에 저장되어 다음 실행에도 유지됩니다.

검색 중에는 메모 드래그 정렬이 비활성화됩니다. 검색 결과의 순서를 실제 메모 순서로 잘못 저장하는 것을 막기 위한 동작입니다.

### 저장 위치

저장 위치:

```text
~/WorKing/memos/<memo-id>.md
```

## 터미널

왼쪽에서 `터미널` 탭을 선택하면 로컬 shell과 SSH 연결을 같은 화면에서 관리할 수 있습니다.

### 로컬 터미널

`+ 로컬`을 눌러 이름을 지정합니다.

- Windows: `cmd.exe`
- macOS/Linux/Crostini: 환경변수 `SHELL`
- `SHELL`이 없으면 `bash`, 이후 `sh`

프로필을 선택하면 PTY/ConPTY 세션이 시작됩니다. 다른 업무/메모/터미널로 이동해도 앱 실행 중에는 프로세스가 유지됩니다.

### SSH 프로필

`+ SSH`에서 다음 값만 지정합니다.

- 이름
- Host
- Port
- User

비밀번호나 private-key passphrase를 저장하는 필드는 없습니다.

SSH 프로필을 선택하면 내부적으로 운영체제의 `ssh` 클라이언트를 직접 실행합니다.

```text
ssh -p <port> <user>@<host>
```

처음 연결이면 host key 확인 메시지가 그대로 표시될 수 있습니다.

```text
Are you sure you want to continue connecting (yes/no)?
```

비밀번호 인증을 사용하는 서버라면 다음 프롬프트에서 직접 비밀번호를 입력합니다.

```text
ubuntu@example.com's password:
```

비밀번호 입력은 PTY/ConPTY로 SSH에 바로 전달됩니다. 앱은 비밀번호를 별도로 받거나 저장하지 않으며, SSH가 echo를 비활성화하므로 입력 문자는 화면에도 표시되지 않습니다.

### 직접 키 입력

터미널 화면을 클릭한 뒤 바로 입력합니다. 이전의 별도 명령어 입력창은 사용하지 않습니다.

- `Enter`: 현재 명령 실행
- `Tab`: Qt 포커스 이동을 막고 PTY/ConPTY로 직접 전달해 shell Tab completion 실행
- `↑ / ↓ / ← / →`: shell에 방향키 전달
- `Ctrl+C`: foreground 명령 중단
- `Ctrl+D`: EOF
- `Ctrl+Shift+C`: 선택한 출력 복사
- `Ctrl+Shift+V`: 클립보드 내용을 터미널에 입력
- `중지`: Ctrl+C와 동일
- `재시작`: 현재 shell/SSH 연결 재시작
- `지우기`: 출력 화면만 비우기
- `clear` / Windows `cls`: shell의 clear-screen 출력을 인식해 화면 초기화

따라서 shell에 Docker completion이 설치되어 있다면 다음처럼 원래 shell의 자동완성을 사용할 수 있습니다.

```bash
docker logs -f my_<Tab>
```

### Streaming 명령

```bash
docker logs -f my_service
tail -f application.log
```

같은 명령의 출력도 계속 받을 수 있습니다. `Ctrl+C`를 누르면 foreground 명령만 중단하고 로컬 shell 또는 SSH 세션은 계속 사용합니다.

### ANSI 색상 출력

로그와 일반 CLI 명령에서 사용하는 ANSI SGR 서식을 화면에 반영합니다.

- 기본 16색 및 밝은 16색
- 256색 팔레트
- 24-bit True Color
- foreground/background 색상
- 굵게, 밑줄, 기울임
- ANSI reset과 출력 청크 사이에 이어지는 색상 상태

따라서 `grep --color=auto`, `ls --color=auto`, `git status`/diff, 컬러 로그처럼 PTY에 ANSI 색상을 출력하는 명령은 색상을 유지해 표시합니다. 출력 도중 ANSI escape sequence가 나뉘어 전달되어도 다음 청크와 이어서 처리합니다.

### 터미널 목록 순서

로컬/SSH 터미널 항목을 목록 안에서 드래그해 순서를 변경할 수 있습니다. 변경 순서는 `~/WorKing/config/terminal-sessions.json`의 세션 배열 순서로 저장되어 다음 실행에도 유지됩니다.

### 프로필 유지

로컬/SSH 프로필은 `~/WorKing/config/terminal-sessions.json`에 저장됩니다.

SSH 프로필에 저장되는 정보는 이름/Host/Port/User뿐이며 비밀번호는 저장하지 않습니다.

앱을 종료하면 실제 shell/SSH 프로세스는 종료됩니다. 다음 실행에서는 프로필 목록만 복원되고, 해당 프로필을 선택할 때 새 연결을 시작합니다.

### 대량 로그 처리

`docker logs -f`, `tail -f`처럼 출력량이 많은 명령 때문에 앱 전체가 느려지는 것을 줄이기 위해 터미널 출력을 바로 한 줄씩 렌더링하지 않습니다.

- 약 50ms 단위로 출력을 묶어서 화면에 반영
- 화면 보존: 최근 약 1,800줄
- 문자량이 큰 출력: 약 0.8MB를 넘으면 오래된 내용 정리
- 보이는 터미널의 렌더 대기 버퍼: 최대 약 512KB
- 숨겨진 터미널의 대기 버퍼: 최대 약 128KB
- 숨겨진 세션은 화면을 계속 다시 그리지 않음
- 처리 속도보다 출력이 훨씬 빠르면 오래된 대기 로그 일부를 생략

로그가 생략된 경우 터미널에 다음 안내가 표시됩니다.

```text
[출력량이 많아 오래된 터미널 로그 일부를 생략했습니다.]
```

터미널은 로그 보관소가 아니라 작업용 화면이므로 무제한 scrollback은 유지하지 않습니다.

### 터미널 테마

현재 선택한 앱 테마에 맞는 터미널 전용 배경/텍스트/선택 색상을 적용합니다. 테마를 변경하면 터미널 색상도 함께 즉시 변경됩니다.

### 제한

Linux/macOS/Crostini에서는 PTY, Windows에서는 ConPTY를 사용합니다.

키 입력과 streaming I/O는 실제 pseudo-terminal로 처리하고 로그용 ANSI 색상/서식은 지원하지만, ANSI cursor/screen 명령 전체를 구현한 terminal emulator는 아닙니다. `vim`/`vi`, `nano`, `top`/`htop`, `less`/`more`, `watch`, `fzf` 같은 전체 화면 TUI는 표시가 제한될 수 있습니다. 터미널 하단의 `⚠ 전체화면 TUI 미지원` 안내에 마우스를 올리면 같은 제한 범위를 확인할 수 있습니다.

## DB Viewer

왼쪽에서 `DB` 탭을 선택하면 MySQL과 PostgreSQL 연결을 여러 개 등록해 테이블을 조회할 수 있습니다.

### 연결 프로필

`+ 연결`에서 다음 값을 입력합니다.

- 이름
- DB 종류: MySQL / PostgreSQL
- Host / Port
- Database
- User
- Password

연결 프로필에는 비밀번호를 저장하지 않습니다. `~/WorKing/config/database-connections.json`에는 이름/DB 종류/Host/Port/Database/User만 저장되며, 입력한 비밀번호는 앱 실행 중 메모리에만 유지됩니다. 앱을 다시 실행하면 연결 시 비밀번호를 다시 입력합니다.

`연결 테스트`로 저장 전에 접속 여부를 확인할 수 있습니다. 연결 테스트도 백그라운드에서 실행하므로 응답이 느린 DB 때문에 편집 창 전체가 멈추지 않습니다.

### Schema / Table 탐색

프로필을 선택하고 `연결 / 새로고침`을 누르거나 프로필을 더블클릭하면 먼저 접근 가능한 schema/database 목록만 불러옵니다. schema를 펼칠 때 해당 table/view 목록을 조회하므로 테이블이 많은 DB에서도 초기 연결 대기 시간을 줄입니다.

- MySQL: 시스템 schema를 제외한 database/schema 목록
- PostgreSQL: `information_schema`, `pg_*`를 제외한 schema 목록
- table과 view 모두 표시
- 왼쪽 `테이블 검색`: 현재 연결의 메타데이터를 서버에서 검색
- `최근 테이블`: 연결별 최근 10개 테이블/뷰 저장

테이블을 선택하면 오른쪽에서 다음 탭을 사용할 수 있습니다.

- `데이터`: 실제 row 조회
- `컬럼`: 컬럼명/타입/NULL/기본값/PK 확인
- `SQL`: 간단한 Read Only SQL 실행

### 데이터 조회

전체 테이블을 한 번에 읽지 않고 페이지 단위로 조회합니다.

- 페이지 크기: 50 / 100 / 200행
- 이전/다음 페이지 이동
- 컬럼 헤더 클릭 시 DB 서버의 `ORDER BY`로 전체 결과 정렬
- 간단한 WHERE 조건 적용
- 셀 우클릭으로 `이 값으로 필터`, `이 값 제외`, `NULL만 보기`
- 선택 셀 TSV 복사 및 헤더 포함 복사
- 현재 페이지 CSV 저장

WHERE 입력란에는 `WHERE` 키워드 없이 조건만 입력합니다.

```sql
status = 'ERROR' AND id > 100
```

세미콜론, SQL 주석, 변경 SQL 키워드는 WHERE 조건에서 차단합니다. 문자열 안에 들어 있는 `update`, `delete` 같은 일반 텍스트는 변경 SQL로 오인하지 않도록 구분해서 검사합니다.

### Read Only SQL

SQL 탭은 조회 목적 전용입니다.

허용 시작 구문:

- `SELECT`
- `WITH`
- `SHOW`
- `DESCRIBE` / `DESC`
- `EXPLAIN`

`INSERT`, `UPDATE`, `DELETE`, `DROP`, `ALTER`, `TRUNCATE` 등 변경 SQL은 앱에서 차단하며, DB 세션에도 Read Only 설정을 적용합니다. SQL 결과는 최대 500행까지 표시합니다.

이 보호 기능은 DB 권한을 대신하지 않습니다. 운영 DB는 DB 계정 자체도 SELECT 권한만 가진 계정을 사용하는 것을 권장합니다.

### DB 드라이버

- MySQL: PyMySQL
- PostgreSQL: psycopg 3

원격 DB 조회와 연결 테스트는 UI가 멈추지 않도록 백그라운드 작업으로 처리하며, 기본 연결 timeout은 5초, statement/read timeout은 약 30초로 제한합니다.

## 폰트 설정

`설정 → 폰트...`에서 앱 UI와 터미널의 폰트를 별도로 설정합니다.

### 앱 폰트

현재 운영체제에서 사용할 수 있는 일반 폰트와 8~32pt 크기를 선택할 수 있습니다. `시스템 기본 폰트`를 선택하면 OS 기본 UI font family를 사용합니다.

### 터미널 폰트

터미널은 정렬과 shell 출력 가독성을 위해 고정폭 폰트만 선택 목록에 표시합니다. `시스템 기본 고정폭 폰트`를 선택하면 OS가 권장하는 fixed font를 사용합니다.

변경 내용은 저장 즉시 기존 화면과 열려 있는 터미널 세션에 적용됩니다.

## CPU / RAM 표시

앱 하단 상태바 왼쪽에는 WorKing 프로세스 자체의 CPU / RAM 사용량이 표시됩니다.

```text
CPU 3.2% · RAM 148 MB
```

약 1.5초 간격으로 갱신합니다. 시스템 전체 CPU/RAM 사용량이 아니라 이 앱 프로세스가 현재 사용하는 양입니다.

`설정 → CPU / RAM 표시`에서 표시 여부를 변경할 수 있습니다. 끄면 라벨을 숨기고 리소스 측정 타이머도 중지합니다. 설정값은 `~/WorKing/config/settings.json`에 저장됩니다.

## 전체 검색

좌측의 `전체 검색`에 단어나 문구를 입력하면 `reports/` 아래의 모든 일일 문서를 검색합니다.

검색 대상은 업무 제목, 링크 이름, URL, 주요 내용, 상태입니다. 직접 수정한 Markdown의 일반 텍스트와 이전 버전의 이전 업무 데이터도 검색됩니다.

결과에는 날짜, 업무 상태, 업무 제목, 일치한 내용이 표시됩니다.

현재 업무 결과를 클릭하면 해당 날짜를 열고 일치한 업무를 선택합니다. 이전 버전 데이터나 일반 Markdown 결과는 해당 날짜 문서를 엽니다.

검색어를 지우면 기존 연도/월/날짜 탐색으로 돌아갑니다.

## 과거 문서

왼쪽에서 연도와 월을 선택하면 해당 월의 문서를 확인할 수 있습니다.

날짜를 선택하면 과거 문서를 열고 수정할 수 있습니다.

## Markdown 파일 위치

```text
~/WorKing/reports/YYYY/MM/YYMMDD.md
```

예:

```text
~/WorKing/reports/2026/09/260923.md
```

## 일일보고

`일일보고 작성`에서 날짜, 상단 문구, 꼬리말을 확인한 뒤 보고서를 생성합니다.

기본 분류:

- 진행 업무: 진행중 + 완료
- 예정 업무: 진행중 + 예정

두 제목은 `설정 → 일일보고 설정...`에서 변경할 수 있으며 출력 시 대괄호는 붙지 않습니다.

필요하면 생성 전에 상단 문구와 꼬리말을 임시로 수정할 수 있습니다.

상단 문구 다음에 설정한 진행 업무 제목이 이어집니다. 날짜 제목도 상단 문구의 날짜 토큰으로 직접 구성할 수 있으며, 상단 문구와 꼬리말의 줄바꿈은 입력한 그대로 유지됩니다.
